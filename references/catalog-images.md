# 透明主图/规格图

来源：[R01](source-images/resource-slots/R01_主图规范.jpg)，从资源位规范PDF第1页提取；来源记录见 [resource-sources.json](resource-sources.json)。本文件中的“主图”不是详情头图S22，也不是轮播首图。

| 项目 | R01标注 |
|---|---|
| 画布 | 800×800px，72dpi |
| 文件 | PNG，透明背景，≤300KB |
| 商品安全区 | 中央640×640px；由居中几何得x/y均为80–720 |
| 构图 | 产品主体完整、居中，安全区内尽量贴近边缘；清晰、正视角度优先 |
| 禁用 | 背景色、额外文字/标签/logo/卖点、投影、描边、马赛克、噪点、偏色、拉伸 |

按此顺序处理：

1. 核对该SKU的主机、豆子/配件数量与颜色，选择本款透明前景；原图是白底JPG时先取得可靠抠图，不能把白底改标为透明PNG。
2. 按实际透明前景边界等比缩放，长边贴640px，短边居中；不能为同时贴满四边把非正方形产品拉伸。实物角度、结构和配件不能因适配而改变。
3. 实测alpha包围盒处于安全区。仅有800×800画布并不证明主体安全；检查淡阴影、孤立像素和遗漏配件。
4. 逐张目视核对外观、编号、颜色、轮廓、无额外文字及阴影。自动alpha检查无法判断是否漏画了一个配件。

商品原有的数字、图案等属于产品外观，保留真实样式；“不添加文字”不授权删除实物标识。多色SKU若用户指定同轮廓，复用同一角度、摆位和输出框，核对原始图素轮廓；相同框不等于已经做到像素级同轮廓。

辅助脚本 `kind: catalog` 仅接受含真实透明区域的PNG前景，自动等比放到中央640框，导出透明PNG并检查实际alpha边界。它不抠图、不生成商品结构、不验证配件数量。KB按保守十进制300000 bytes实现，这是导出计量选择，不能改写原文“300KB”。

# 制作、导出和单图修改（项目工作规则）

## 工具边界

AI负责识别图位、选择模块、编排真实信息并调用可用的生图工具。真实字体排版可使用PS或Sharp；本仓库提供最小的Sharp辅助程序，不含生图服务、不抠图、不自动识别任意商品，也不自动发布。

Node.js≥22.13，安装依赖后运行 `pnpm test`、`pnpm validate`。仅查规范不需要这些依赖或API key。生成有文字图时通过 `--fonts` 指定含MiSans-Regular.otf、MiSans-Medium.otf、MiSans-Semibold.otf的目录；缺字体直接报错，不换其他字体蒙混通过。字体不随仓库分发。

## 商品工作目录

商品素材和结果保留在仓库外或被忽略的 `runs/`，不要提交私有商品图、对话、认证资料、Logo或字体。按商品保存事实、文案和每张图的清单。每张图有稳定ID、revision、图位、素材路径和哈希、排版参数、引用文案ID及输出记录。

预览示例：

```sh
node scripts/render-image.mjs /path/to/image.json --out /path/to/run
node scripts/verify-image.mjs /path/to/run/image-id.png --report /path/to/run/image-id.report.json
```

图像/商品清单格式见 [render-manifest.md](render-manifest.md)。默认preview，报告待目检；正式导出显式加 `--production`，不自动把草稿改为已审。脚本支持透明主图、方/横场景、轮播首图和一行标题+描述轮播。详情仍按对应原规范制作；辅助脚本没有实现的版式不能宣称已经自动验收。

## 图素和文字

默认保留原来的摄影场景，去字适配不等于抠图换场景或另外生成背景。用户提供的原图足够使用时，不主动做扩图、场景重建和产品重绘；先解决取图、去旧字、裁切、等比缩放及新文字位置。扩图与换场景是确有需要时的备选，不是每套必做环节。

导出的详情图片可能按固定高度从内容中间切开。先按文件编号排序、核对接缝，把同宽正文切片拼接成长图，再按完整商品/场景/模块重新截取；不要把每个切片当作一张完整设计稿。记录每片在长图中的y坐标与截取框，排除推荐其他商品、通用店铺售后等无关内容。拼接不扩图、不重绘，原图宽度一致时保留原始像素；宽度不同先说明处理方式。聊天截图默认用于说明位置、文件名或问题，实际制作回到用户指定的原素材；只有用户明确把截图作为编辑对象时才用截图落稿。

项目限定单张最高1680px时，先把详情内容按1080px宽建立，再在自然高度超过1680px的模块中选择语义切点拆成多张；不得把整段缩小塞进1680px。主体详情模块同时要求高度不小于宽度，1080px宽时应为1080–1680px高；原始摄影画面较矮时，应完整保留画面并与标题、说明或完整卡片组成纵向模块，不输出不足1:1的横条，也不拉伸照片。切点不能穿过商品主体、标题/正文行或小卡片。小卡片跨原切片时先拼接复原，按完整卡片组分段；若整组过高，按卡片之间的自然间隔拆页。同一场景只使用一次，不重复出现在多张详情或多张轮播图中；页面数量由有效且不重复的素材决定，不硬凑固定张数。轮播每张应承担不同信息：主场景、玩法、功能、细节、配置等分别选取对应原图，而不是只换标题复用背景。

1. 先盘点本款原主图、SKU、详情页和实拍。优先原图适配，主图/轮播不足时先从详情页选完整、清晰的摄影画面补充；来源文件夹和长图位置不是图位用途限制。
2. 去旧文案并按新图位排版；背景中可安全去掉的文字不应触发整件商品重绘。旧字覆盖商品时优先换同款另一张原图、调整裁切；确需局部修补时记录区域并重新核对。保留实物印花与标识，区分实物文字、旧广告文字、动作残影和标注箭头，不能一并误删或把宣传特效当作真实配件。
3. 无字场景保存为共同母图时，清单复用同一源文件与哈希。不同尺寸分别检查主体边界，横图必要时另做背景扩展，不能压扁或悄悄更换产品摆放。
4. 先检查导出文件的像素、格式、大小、alpha和边界，再逐张查看外观、文案语义、主体是否缺件、文字是否压图。不要仅凭脚本exit=0宣称全部合规。

比例适配先裁切，但必须保持等比，禁止横向或纵向拉伸；放不下完整商品时可抠取原图商品合成、只扩背景，并保留商品区域。轮播使用铺满裁切前逐张核对四边，商品主体、遥控器、配件和配置对象都不得被画布截断。横向摄影画面无法安全铺满方图时，保留整幅横图，用连续背景、留白或文字区完成方形画布，不以 `cover` 裁掉关键对象。不要默认用大块纯色外框把照片缩成小卡片；需要整张场景时做连贯背景，轮播标题仍在上方居中，详情头图名称与slogan仍按左对齐模板。纯色背景本身可按资源位规范使用，不能把这条实施偏好冒写成官方禁止纯色。

详情版式按素材角色选择，不固定套同一模板：有完整场景和清晰主体时优先采用S04类“原图满版＋直接排字”；卖点汇总、操作说明、参数和配置可采用S03类信息模块。两类版式可交替形成节奏，但不能把全部正文压缩成重复的“白底＋上方文字＋方框图片”。原详情中存在有效且不重复的场景、细节或卡片时继续保留；页数由内容决定，不为固定张数删减有效素材，也不为凑数重复同一场景。

白字默认使用单层纯白文字，不自动叠加描边、投影或模糊阴影。背景对比不足时先换文字落点，或在局部使用轻量、连续的明暗渐变；不得重复合成同一阴影层。导出后放大检查文字边缘，出现双轮廓、重影或脏边即返工。

安全区不足时优先更换本款另一张原图、调整等比裁切或选用其他完整场景。未经用户确认，不使用镜像补边、重复物件、矩形贴片、空场景重建，或“先擦掉商品再放回”的方式强行制造安全区；这些处理容易产生拼接、投影和外观偏差。无文字实景方图与轮播第一张可按项目要求使用同一母图，横图只调整画幅，不重新生成另一套场景。

优先在原场景里调整文字，不以“文字绝对不能碰到任何产品像素”为由强制生成新场景或加入大块空白。官方对应模块的避让要求仍按其来源记录；用户明确允许适度叠字等变化时，作为当前项目选择留档，确保印花、操作部位和必要信息可辨认，不把项目例外改写为通用官方规则。

只在原图不能满足所需内容、用户明确选择重绘等实际需要时生成新的商品/场景。固定主机、配件、数量、颜色、印花方向、图案细节、按键、接口和镜头，未知处不补造。用户要求重绘时也须逐张对照原图；一张印花正确不代表其他角度已正确，不能用“有八条腿”代替完整图案与方向核对。图像工具输出不可靠时明确指出，保留原图复用选项。

记录每张图的源文件哈希、裁切框、缩放、背景扩展与修补区域。若声明商品像素保留，需用实际遮罩/合成过程核对受保护区域，不能仅凭提示词声称；原图缩放、压缩后不再声称最终JPG逐像素等同源图。文案另用真实字体排版，不沿用不合规或未经核实的旧宣传内容。

## 只修改某一张

收到“只改03标题/放大主体”时，读取该图清单、依赖事实与上一版，不重编整套。记录修改点，增加revision，只渲染该ID；保留旧版在另一输出目录。不要因复用同一文件名而丢失上一版。

渲染器拒绝覆盖同一ID的不同revision，除非显式 `--replace`（仅供重跑同一试验，不作为保留历史的替代）。输出写入临时文件后改名；失败不留下伪成功报告。批量中任何未改图以文件哈希确认保持不变。

若用户纠正事实而不仅是措辞，先列出引用该事实的所有图位，更新相关草稿。SKU要求同轮廓时共用摆位参数并比对图素轮廓；共用输出框不能证明原始图素完全相同。

## 验证能证明什么

自动检查尺寸、字节、透明包围盒和由清单声明的主体框。照片的主体框须人工核对且绑定原图哈希，不能把整张照片当成商品框。主体框缺失、AI图素未核准、文案未审等都保留review项，不给全合规结论。

文字居中/上部位置按独立的官方模板证据核对，不由“生成时写了什么”自证正确。文字内容、阴影、缺失配件、材质/功能/认证语义等不在这些像素检测的证明范围。生产模式也不会把这些目检自动标成通过。

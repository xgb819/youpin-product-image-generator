# 上架七字段文案：纯文字模式

AI根据既有商品事实撰写，辅助程序检查字数、格式与绑定事实并导出文字。此模式不生成图片，不需要字体、Sharp、PS或生图服务。

来源：[用户提供的规范摘录](source-texts/listing-copy-source.md)、[摘录与原件哈希](listing-copy-source.json)。运行参数在 [listing-fields.json](listing-fields.json)。原文自述2022-08-26生效，外链及当前后台未独立验证。

| 字段 | 最大字数 | 尽量接近范围 |
|---|---:|---:|
| 商品名称 | 30 | 27–30 |
| 商品简称 | 8 | 6–8 |
| 商品描述 | 30 | 27–30 |
| 商品简述 | 13 | 11–13 |
| 核心卖点1 | 24 | 21–24 |
| 核心卖点2 | 24 | 21–24 |
| 核心卖点3 | 24 | 21–24 |

接近范围是用户“尽量写满，差几个字可以”的实现目标，不是官方最低字数。真实、自然、不重复优先；不足时可短，不填充新功能、不堆重复词。超长整句改写，不机械截断。空格、数字、英文、标点计入，使用UTF-16码元保守计数，同时给出Unicode码点数；普通中文各计1。避免Emoji、隐藏字符；后台计数尚未实测。

原文L01名称30字，L02又写20字，两处均保留。按用户本次明确的30字执行，不静默改为20或谎称已确认最新平台规则。原文提到8项而用户只要7项，不补造第8项。

## 生成与复用

1. 读取当前商品工作目录的product_id与facts/copy，复用品牌、颜色、配置、功能及来源。合并新纠正，不跨商品套资料，不逐字段重问。
2. 从本款资料和已核准的头图/前几页选候选卖点，回事实表核对。AI图、近似款和竞品文字不能作为本款功能证据。
3. 默认直接输出一套首选七字段+字数，不先问风格。只对真正缺失的事实集中说明，其余内容继续；信息不足允许短文案，不虚构3条卖点。
4. 每个字段为factual并绑定assertions。三条核心还各有primary_fact_id，且互不相同；不要用creative避开功能核验。多SKU共同字段必须适用全部所选SKU；有差异时明确标注并建立适用组合的整体事实记录，不暗取高配版。
5. 用户只改单字段时，仅更新对应copy，其他六项保留。新增revision留旧版；已确认事实继续复用。事实变化时再列受影响字段，不强行重问整套。

## 名称及卖点格式

- 普通长名称：确认品牌+一个英文空格+系列（有依据时）/核心特点/品类。品牌优先中文名，正式品牌另有要求则记录。名称不含“有品”“小米有品”，不靠其他空格和符号堆句。
- 简称：特点+品类，品牌可选，不能为塞品牌超8字。长名称建议不加规格，不能为凑长标题乱加型号/参数。
- 描述、简述和核心点用英文逗号`,`断句，需引号时用英文双引号。不用竖线、「」、・、【】、+等断句；核心点结尾不加句末标点。
- 三条核心不能重复，也不能直接复制商品名称。检查器只能发现归一后的完全重复和主事实重复，中文同义重复仍需人工看。
- 只写商品功能/特征，不加促销、折扣、运营信息。示例词扫描不等于完整法律禁词库，不据词表宣称全面合规。
- 规格单位mL、m、km、cm、g、kg，软件App；常见英文首字母与专有名词例外按真实资料，不能为格式化改掉品牌或型号含义。
- 不无证添加明星/专家推荐、米家或小米等关联。已确认接入米家且该句绑定此事实时才放行“接入米家”。普通自动导出不实现明星授权推荐的例外放行，有实际需求需专项核对；不把程序限制说成官方禁止全部明星推荐。平行类目斜线可用已确认的parallel_categories_fact_id显式支持，普通标题不滥用斜线。

## 清单与命令

沿用 [product-facts.md](product-facts.md) 的商品JSON。清单字段值是copy ID，而不是直接绕开证据的裸文本。真实商品资料留工作目录，不进公共仓库。

```json
{
  "schema_version":1,
  "id":"listing-main",
  "revision":1,
  "product":"product.json",
  "sku_ids":["green","beige"],
  "brand_fact_id":"brand",
  "fields":{
    "product_name":"listing-name",
    "short_name":"listing-short-name",
    "description":"listing-description",
    "summary":"listing-summary",
    "selling_point_1":"listing-point-1",
    "selling_point_2":"listing-point-2",
    "selling_point_3":"listing-point-3"
  }
}
```

```sh
node scripts/export-listing-copy.mjs /path/to/listing.json --out /path/to/run
```

一次得到七字段TXT、字数表Markdown、含依据/断言/哈希的JSON。默认草稿直接生成，不增加逐字段确认步骤；不触发任何图片制作。

正式导出加 `--production`：每条copy为approved，review.source存在，review.text_sha256匹配当前文字。有效既有确认可复用，改字后不能沿用旧文字哈希。程序不代填用户确认，也不自动发布到后台。

字数/格式通过不等于自然语言、实物、授权或法律审核通过。未知和明确不存在的功能不要进入候选文案；结构化断言仅能检查已登记值的矛盾，不能识别所有隐含承诺。
